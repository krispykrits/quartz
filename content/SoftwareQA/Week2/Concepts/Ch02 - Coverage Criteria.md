# Coverage Criteria
**Source:** Section 2.4.

## Problem
The input space is practically infinite. The chapter's three-32-bit-integer example produces over 80 octillion possible inputs.

## Two Questions
1. How do we search?
2. When do we stop?

## Definition
A **test requirement** is an element of a software artifact a test must satisfy/cover. A **coverage criterion** is a rule or collection of rules that yields test requirements.

## Benefits
- systematic input-space search;
- less redundancy;
- stopping rules;
- traceability;
- regression support;
- automation potential.

## Four Mathematical Structures
The chapter says most criteria can be organized around:
1. input domains;
2. graphs;
3. logic expressions;
4. syntax descriptions / grammars.

## Exam-Level Understanding
Coverage does not mean exhaustive testing. It means satisfying an explicitly chosen structural rule.
